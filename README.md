# Delivery API

**Зачем этот API:** чтобы клиент мог оформить доставку посылки, следить за ее статусом, поменять адрес и отменить доставку, пока посылка еще не отправлена.

## Что в репозитории

| Путь | Что это |
|---|---|
| [api.yaml](api.yaml) | Спецификация OpenAPI 3.0.3 |
| [service/](service/) | Сервис на Python (Flask + connexion), сгенерированный по спеке |
| [service/delivery/controllers/deliveries_controller.py](service/delivery/controllers/deliveries_controller.py) | Вся логика: хранение в памяти и обработчики эндпоинтов |

## Часть 1 · Спецификация

Базовый URL: `http://localhost:8080/api/v1`, авторизация: `Authorization: Bearer <token>`.

| Запросы | Путь | Summary | Коды |
|---|---|---|---|
| GET | `/deliveries` | Список доставок текущего клиента (фильтр `status`) | 200, 400, 401 |
| POST | `/deliveries` | Оформить доставку (цена считается на сервере) | 201, 400, 401 |
| GET | `/deliveries/{id}` | Одна доставка и ее статус | 200, 401, 403, 404 |
| PATCH | `/deliveries/{id}` | Изменить адрес или комментарий | 200, 400, 401, 403, 404, 409 |
| DELETE | `/deliveries/{id}` | Отменить доставку | 204, 401, 403, 404, 409 |

Коды ошибок:
- **401** — «не знаю, кто ты»: токена нет или он недействителен.
- **403** — «знаю, кто ты, но нельзя»: это доставка другого клиента.
- **404** — доставки с таким id нет.
- **409** — действие недоступно в текущем статусе: посылка уже в пути, доставлена или отменена.
- **400** — тело или параметры не прошли валидацию (нет адреса, вес больше 30 кг, неизвестный статус).

**DTO** в `components/schemas`: на вход `DeliveryCreateRequest` и `DeliveryUpdateRequest`, на выход `Delivery` и `Error`, плюс перечисление `DeliveryStatus`.
**Что не отдается наружу:** id клиента (сервер берет его из токена), id курьера, себестоимость. Клиент не может сам задать `status` и `price`: их выставляет сервер.

Валидация: `openapi-generator-cli validate` -> `No validation issues detected.` Спеку можно открыть в [editor.swagger.io](https://editor.swagger.io) или импортировать в Postman (Import -> OpenAPI).

## Часть 2 · Кодогенерация

Генератор `python-flask`, openapi-generator v7.10.0. Генератор написан на Java, а Java на машине нет, поэтому запускал его через Docker:

```bash
docker run --rm -v "${PWD}:/local" openapitools/openapi-generator-cli:v7.10.0 \
  generate -i /local/api.yaml -g python-flask -o /local/service \
  --additional-properties=packageName=delivery,serverPort=8080
```

Запуск:

```bash
cd service
docker build -t delivery-api .
docker run --rm -p 8080:8080 delivery-api
# Swagger UI: http://localhost:8080/api/v1/ui/
```

Тестовые токены: `alice-token` (доставки 1 и 3) и `bob-token` (доставка 2). Доставка 1 в статусе `created`, ее можно менять. Доставки 2 и 3 уже `in_transit`, поэтому на изменение придет 409.

```bash
H='Authorization: Bearer alice-token'
curl -H "$H" localhost:8080/api/v1/deliveries          # 200
curl localhost:8080/api/v1/deliveries                  # 401
curl -H "$H" localhost:8080/api/v1/deliveries/2        # 403 — доставка Боба
curl -X DELETE -H "$H" localhost:8080/api/v1/deliveries/3   # 409 — уже в пути
```

## Часть 3 · Как делал

**С агентом:** Claude Code (модель Claude Opus 5.5) в VS Code.

**Итоговый промпт:**

```text
Роль: ты backend-разработчик, проектируешь API по принципу contract-first.

Задача: спроектировать REST API «Служба доставки» в формате OpenAPI 3.0
и сгенерировать по нему сервис на Python.

Часть 1. api.yaml в корне репозитория:
- 5 эндпоинтов на разные HTTP-глаголы над ресурсом «доставка»:
  GET-список (фильтр по статусу), GET-одна, POST (оформить),
  PATCH (сменить адрес/комментарий), DELETE (отменить).
- У каждого эндпоинта: summary, параметры, успешный ответ и ошибки с причиной.
  Четко разведи 401 («не знаю, кто ты») и 403 («знаю, но нельзя» — чужая доставка),
  плюс 404, 400 и 409 (нельзя менять/отменять уже отправленную доставку).
- Авторизация Bearer-токеном, владельца сервер берет из токена.
- Все DTO в components/schemas, входные и выходные отдельно. Внутренние поля
  (id клиента, id курьера, себестоимость) в DTO не попадают; статус и цену
  выставляет сервер, клиент их не передает.
- Провалидируй спеку (openapi-generator validate).

Часть 2. Кодоген:
- openapi-generator-cli, генератор python-flask, вывод в ./service.
  Java локально нет, запускай через Docker-образ openapitools/openapi-generator-cli.
- Кода по минимуму, без лишних надстроек: in-memory хранилище прямо в контроллере,
  без БД, без отдельных слоев и модулей. Только чтобы каждый эндпоинт реально работал.
- Сервис должен запускаться в Docker. Прогони curl'ом все эндпоинты и все коды ответов.

```

**Что поправили руками после генерации** (без этих правок сгенерированный каркас не работал):

1. **`requirements.txt`**: генератор закрепил `Flask == 2.1.1`, а Werkzeug оставил без версии. С Werkzeug 3.x этот Flask падает при импорте, поэтому добавлен `Werkzeug == 2.2.3`.
2. **`Dockerfile`**: `python:3-alpine` заменен на `python:3.11-alpine`, с ним старый connexion 2.x работает стабильно.
3. **Имя аргумента тела**: в заглушках тело называлось `delivery_create_request` / `delivery_update_request`, а connexion 2.x передает его в `body`. Из-за этого POST и PATCH падали с ошибкой 500. Аргумент переименован в `body`.
4. **`security_controller.py`**: заглушка пропускала любой токен. Теперь неизвестный токен дает 401.
5. **`deliveries_controller.py`**: заглушки `return 'do some magic!'` заменены на работающие обработчики. Добавлены хранение в памяти, проверки 403/404/409 и расчет цены (300 ₽ + 50 ₽ за кг).
6. **`.openapi-generator-ignore`**: туда внесены файлы с ручной логикой, чтобы повторная генерация их не затерла.

**Проверено curl'ом (19 запросов, все коды совпали):**
- GET-список: 200, 401 без токена, 401 с плохим токеном, 400 на неизвестный статус;
- GET-одна: 200, 403, 404;
- POST: 201, 400 без адреса, 400 при весе больше 30 кг;
- PATCH: 200, 400 на пустое тело, 409 для доставки в пути, 403;
- DELETE: 204, 409 при повторной отмене, 403, 404;
- Swagger UI: 200.
